# Contributing to Blitz.gg Troubleshooter

## Branch and PR Flow

- Do not push directly to `master` or `dev`.
- Create your own feature branch from `dev`.
- Open a pull request into `dev`.
- Maintainer reviews and merges into `dev`.
- Maintainer promotes tested changes from `dev` to `master`.

## Release Channels

- `master` publishes stable releases (latest).
- `dev` publishes prereleases (not latest).

## Build Notes

- The release workflow publishes a single-file executable asset named `Blitz.Troubleshooter.exe`.
- Keep changes focused and include a clear PR description.
